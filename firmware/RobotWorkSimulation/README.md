# 팔레트 이송용 UNO 펌웨어

Arduino UNO가 액추에이터와 컨베이어를 구동하고 IR1·IR2로 정차 위치를 감지한다. 팔레트 배출 10초와 대기 0.5초가 지나면 액추에이터 복귀를 시작한다. 통합 모드에서는 QR·DB 배정 확인 후 벨트가 출발한다. 기본값은 IR1 감지 후 5.5초 이송하여 조립 위치 정차, IR2 감지 후 2초 이송하여 최종 정차다. 두 센서의 정차 보정 시간은 실물 정차 위치에 맞춰 확인한다.

| 신호 | UNO 핀 |
| --- | --- |
| 컨베이어 PUL+ / DIR+ | D5 / D6 |
| 액추에이터 드라이버 ENA / IN1 / IN2 | D9 / D7 / D8 |
| IR1 / IR2 출력 | D4 / D2 |

컨베이어 펄스 반주기는 80µs이고 방향 출력은 HIGH다. 센서는 INPUT_PULLUP으로 읽고 LOW가 20ms 지속되면 감지를 확정한다. 자동 시작 시 두 센서가 비어 있어야 하며, 벨트의 각 운전 구간은 30초에 오류 정지한다.

## 모드와 시리얼 명령

USB 시리얼은 115200 baud, 줄바꿈으로 명령을 끝낸다. 시작 배너는 `READY UNO_TRANSFER_V3`다.

| 명령 | 동작 |
| --- | --- |
| `a <회차번호>` | 통합 회차의 팔레트 배출을 시작한다. 회차번호는 1~4294967295의 십진 정수이며 실행 중인 UNO에서는 직전 통합 회차보다 커야 한다. |
| `START_TRANSFER <회차번호>` | 배출 후 QR 판독과 서버의 DB 배정이 모두 끝난 회차의 최초 이송을 허용한다. |
| `demo` | 조립 장비가 분리된 단독 이송 시연. 액추에이터 복귀와 첫 이송을 함께 시작하고, 조립 위치에서 모의 대기 시간이 지나면 벨트가 다시 출발한다. |
| `s` | 액추에이터와 벨트 정지. 통합 회차의 QR 배정 또는 조립 완료 대기 중에는 정지 잠금으로 전환한다. |
| `j`, `k` | 대기 상태에서 액추에이터를 1초간 전진 또는 복귀한다. |
| `q` | 진행 중인 회차의 QR 인식을 기록한다. 벨트 출발 승인은 `START_TRANSFER`로 한다. |
| `?`, `T <요청번호> <IR1이송ms> <모의대기ms> <IR2이송ms>` | 시간 조회·설정. 설정은 대기 상태에서만 변경되며 시작 시 회차 값으로 고정한다. |

시간 설정은 요청번호 1 이상, 각 이송 0~25000ms, 모의 대기 0~30000ms이며 시간 값은 500ms 단위다. 기본값은 5500/3000/2000ms다. `TIMING:`으로 적용값을 확인한다. 가운데 시간 값은 `demo`에만 적용한다.

## 통합 회차 시리얼 흐름

1. 배출과 대기가 끝나면 UNO가 벨트를 정지 상태로 유지하고 `PALLET_EJECTED:<회차번호>`를 보낸다. 메인 PC는 카메라 1로 QR을 읽고 같은 회차의 수락 주문과 팔레트 배정을 DB에 저장한다.
2. QR 판독과 DB 저장이 모두 성공한 뒤 현장 Pi가 `START_TRANSFER <회차번호>`를 보낸다. 배출 후에 들어온 같은 회차의 명령과 비어 있는 IR1·IR2가 확인되면 UNO가 벨트를 출발시키고 `TRANSFER_STARTED:<회차번호>`를 보낸다. 출발 시 센서가 가려져 있으면 정지 잠금으로 전환한다.
3. QR 판독 또는 DB 저장이 실패하면 서버가 같은 회차를 유지하여 재시도하고 UNO는 승인까지 계속 정지한다. 재접속 시 서버는 이미 배출된 팔레트와 DB 상태를 대조한다. 같은 회차를 재개할 때는 다시 배출하지 않고 출발 승인을 새로 판단한다.

### 조립 위치 정차와 재출발

1. UNO가 조립 위치에서 벨트를 정지하면 `ASSEMBLY_WAIT:<회차번호>`를 보낸다. 이때부터 같은 번호의 명령만 받는다.
2. 현장 Pi는 해당 회차의 서버·조립 장비 상태를 확인할 수 있을 때만 `HEARTBEAT <회차번호>`를 보낸다. 첫 수신까지 또는 연속 수신 사이에 2초가 지나면 UNO가 `ERR:ASSEMBLY_LINK_TIMEOUT`을 기록하고 정지 잠금을 유지한다. 정상 운용의 송신 간격은 500ms를 기준으로 한다.
3. 서버가 해당 회차의 조립 완료와 로봇팔의 대기 자세 복귀를 확인하면 Pi가 `ASSEMBLY_DONE <회차번호>`를 보낸다. 이 명령은 같은 회차의 첫 하트비트 수신 이후에만 유효하다. 통신이 유지되더라도 완료 확인 전에는 벨트가 계속 정지한다.
4. 유효한 완료 후 IR2가 비어 있을 때만 재출발하고 `ASSEMBLY_RESTARTED:<회차번호>`를 보낸다. 잘못된 회차나 조립 정차 전의 완료는 무시한다. IR2가 가려졌거나 조립 대기 중 정지 명령을 받은 경우도 정지 잠금으로 전환한다.

### 최종 정차와 인수

IR2 감지와 최종 이송 보정 후 UNO가 벨트 출력을 정지하고 `HANDOFF_READY:<회차번호>`를 보낸다. 서버가 이 회차와 팔레트를 확인한 후 AGV를 호출한다. `CYCLE_DONE:READY_A`는 UNO 구동 종료이며, 서버는 AGV의 하역과 복귀가 끝난 뒤 공정 전체를 완료 처리하고 다음 팔레트를 투입한다.

UNO가 유지되는 동안 정지 잠금은 시리얼 명령으로 해제되지 않는다. 현장에서 벨트·팔레트·로봇팔 상태를 확인하고 물리적으로 안전한 상태를 확보한 뒤 UNO를 재설정한다. Pi와 서버는 재접속·재설정 시 이전 명령과 수신 데이터를 폐기한다. USB 재접속으로 UNO가 재부팅될 수 있으므로 연결 복구만으로 이전 회차를 재전송하거나 새 회차를 시작하지 않는다. 이 시리얼 연동은 공정 제어 조건이며, 현장 비상정지나 물리적 안전 인터록은 별도로 유지한다.

이 PR은 [팀 공정 문서](https://github.com/Esp3ra/2026-Moble-3rd-Team-Project/blob/Alpha/docs/HARDWARE_WORKFLOW.md)의 2~7단계에서 UNO가 맡는 동작을 다룬다. Pi·서버의 명령 전달, QR 재시도와 DB 기록, 로봇팔 상태 확인 및 AGV 호출은 팀 통합 작업 [#15](https://github.com/Esp3ra/2026-Moble-3rd-Team-Project/issues/15)에서 함께 검증한다.
