# 컴파일 검증 결과

검증일: 2026-11-11

## 단독 자동 왕복 추가 후 결과

- 최신 ActuatorJogTest: 로컬 UNO 컴파일 성공, 프로그램 3,292바이트, RAM 213바이트.
- 사용자가 0.5초 양방향 구동, 이후 2초 자동 정지와 s 정지 후 재출발 차단을 정상이라고 보고했다. 직접 장치 계측 결과와 구분한다.
- 새 5초/정지 0.5초/반대 5초 자동 사이클은 실물 미실행이다. 물리 비상정지·외부 끝점 시험도 미실행이다.
- 통합 컨트롤러 기본 비활성화와 기존 컴파일 결과는 유지한다.

## L298N 도입 시 컴파일 결과 (당시 단독 조그 0.5초)

- L298N ENA D9, IN1 D7, IN2 D8로 수정. 통합 코드의 물리 정지/리셋·끝점 요구와 기본 비활성화는 유지.
- 별도 ActuatorJogTest: UNO 컴파일 성공, 프로그램 2,930바이트, RAM 204바이트.
- 통합 코드 기본 설정: UNO 컴파일 성공, 프로그램 9,256바이트, RAM 335바이트.
- 통합 코드 활성 분기(임시 복사본만 true): UNO 컴파일 성공, 프로그램 9,720바이트, RAM 340바이트.
- CLI 1.5.1 / AVR 1.8.8 / AccelStepper 1.64. 단독 시험 코드는 별도 라이브러리 불필요.
- CI에 위 세 가지 컴파일 변형을 구성. 로컬 YAML 파싱과 diff 공백 검사는 통과했다. GitHub 실행 결과는 PR Checks를 확인한다.
- 보드 업로드·실물 구동·정지/리미트 회로 시험은 미실행. 사용자가 어댑터 약 12.3V를 확인한 것은 전원 확인이며 코드 동작 검증과 구분한다.

아래는 최초 BTS7960 가정 코드의 과거 컴파일 기록으로, 최신 L298N 결과가 아니다.

## 수행한 확인

- Arduino CLI로 Arduino UNO(`arduino:avr:uno`) 대상 컴파일 성공.
- Arduino AVR Boards 1.8.8, AccelStepper 1.64 사용.
- 기본 설정(액추에이터 비활성): 프로그램 9,288바이트 / 32,256바이트, 전역 메모리 335바이트 / 2,048바이트.
- 별도의 임시 복사본에서 액추에이터 활성 분기 컴파일도 성공: 프로그램 9,894바이트, 전역 메모리 340바이트.
- 전달용 Config.h는 `ACTUATOR_HARDWARE_VERIFIED = false`로 유지.

## 아직 수행하지 않은 확인

보드 업로드, 실제 컨베이어 및 액추에이터 구동, 버튼·리미트 스위치 입력 시험은 수행하지 않았다. 컴파일 성공은 실제 정지 성능이나 배선·기구의 안전성을 검증한 결과가 아니다.

실물 확인은 `사용 안내.md`의 시험 순서에 따라 진행한다. 액추에이터 모델, 드라이버, 전원, 리미트 배선이 확정되기 전에는 활성화하지 않는다. 비상정지는 소프트웨어 입력과 별도로 구동 전원을 차단하는 하드웨어 회로가 필요하다.
