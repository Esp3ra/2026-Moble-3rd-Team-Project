MOBOT 장비용 라즈베리파이 설치
================================

대상: 컨베이어·액추에이터를 제어하는 UNO 및 USB 카메라.
로봇팔 내장 Pi의 작업 API와 AGV 실물 통신은 이번 패키지에 포함하지 않습니다.
UNO 펌웨어는 기존 RobotWorkSimulation을 사용합니다. 로봇팔 작업 구간은
아직 시간 기반 대기이며 실제 로봇팔 완료 응답으로 전환하는 작업은 별도입니다.

연결 구조
  Pi --HTTPS 요청--> ngrok --터널--> 중앙 Flask/SQLite <-- WPF
Pi는 외부 포트를 열지 않습니다. SSH·포트포워딩·동일 공유기는 필요하지 않습니다.
이 프로그램은 SSH 원격 편집을 제공하는 프로그램은 아닙니다.

1. ZIP을 Pi의 ~/mobot-device 에 풀기
-----------------------------------
압축을 풀었을 때 다음 폴더가 같은 위치에 있어야 합니다.

  ~/mobot-device/raspi_agent/
  ~/mobot-device/pallet_system_uno_sim/

raspi_agent/config.json에는 장비 전용 토큰이 들어 있습니다.
이 파일과 ZIP을 공개 저장소·채팅방에 게시하지 마세요.
서버 DB에는 토큰의 SHA-256 해시만 저장합니다.

2. Python 환경 설치 (Raspberry Pi OS 64-bit, Python 3.10 이상)
-----------------------------------------------------------
  sudo apt update
  sudo apt install -y python3-venv libgl1 libglib2.0-0
  cd ~/mobot-device
  python3 -m venv .venv
  .venv/bin/python -m pip install -r raspi_agent/requirements.txt
  sudo usermod -aG dialout,video "$USER"

그룹 변경 후 로그아웃하고 다시 로그인합니다.
Python 패키지는 Pi에서 설치합니다. Windows의 .venv를 복사하지 마세요.
일부 Pi/OS에서는 OpenCV·NumPy 바이너리 설치에 추가 패키지가 필요할 수 있습니다.
실제 Pi 모델·OS에서 설치 검증은 아직 수행하지 않았습니다.

3. USB 포트와 카메라 번호 확인
-----------------------------
  .venv/bin/python -m serial.tools.list_ports
  ls /dev/video*

raspi_agent/config.json의 serial_port와 camera_index를 맞춥니다.
기본값은 serial_port=/dev/ttyACM0, camera_index=0 입니다.

  server_url: https://YOUR_TUNNEL.ngrok-free.dev
  device_id: uno-pi
  device_token: 이미 작성됨, 변경하지 않음
  demo: false (실제 UNO·카메라 사용)
  serial_port: 실제 UNO USB 포트
  camera_index: USB 카메라 인덱스

서버 등록 모드가 LIVE이면 demo=false여야 합니다.
임의로 demo=true만 바꾸면 서버가 모드 불일치로 거절합니다.

4. 실행
-------
  cd ~/mobot-device
  chmod 600 raspi_agent/config.json
  .venv/bin/python -m raspi_agent.agent --config raspi_agent/config.json

실행 후 기존 UNO 제어 화면 등 다른 프로그램에서 같은 USB·카메라를
동시에 열지 마세요. 에이전트는 파일 잠금으로 중복 실행을 차단합니다.
종료는 Ctrl+C입니다. 정상 종료 시 UNO에 정지 명령을 보냅니다.

5. WPF에서 확인
---------------
관리자 로그인 후 상단에 원격 UNO/LIVE 표시 및 Pi 영상이 들어오는지 봅니다.
실제 카메라의 기존 QR을 치우고 IR1/IR2 비움과 READY를 확인합니다.
대기 주문과 배출 예상 팔레트를 선택하고 실제 시작 위치 확인을 체크한 뒤
'선택 주문 운전 시작'을 누릅니다.

카메라가 읽은 팔레트 일련번호가 예상 팔레트와 일치하면 선택 주문을 DB에
배정합니다. QR에는 일련번호만 있습니다. 주문 정보를 QR 이미지에 쓰지 않습니다.
QR·장비 완료·DB 배정 후 배출 확인을 누르면 Pi에 확인을 요청하고,
Pi의 성공 응답을 받은 뒤 중앙 회차 SUCCESS로 확정합니다.
배송·조립 전체 완료와 팔레트 배정 해제는 별도입니다.

6. 통신과 기록
---------------
Pi는 약 0.4초 간격으로 상태·명령 결과를 보고하고 다음 명령을 받습니다.
영상은 별도 스레드에서 약 2fps로 전송하므로 영상 업로드가 정지 감시를 막지 않습니다.
WPF는 기존처럼 1초 간격으로 운전 세션 heartbeat를 보냅니다.
Pi가 유효한 중앙 응답을 3.5초 넘게 받지 못하면 로컬에서 운전을 중단합니다.
WPF heartbeat가 4초 넘게 끊기면 중앙이 운전 허가를 철회합니다.
USB·카메라 단절 처리와 재연결은 기존 Bench 코드를 재사용합니다.

모든 명령에는 UUID와 3초 유효 시간이 있습니다.
서버는 시작 명령을 한 번만 전달하며 응답이 사라져도 자동 재전송하지 않습니다.
Pi도 commands.sqlite3에 실행 전에 명령 ID를 저장하여 재실행을 차단합니다.
서버/Pi 재시작·연결 복구 후 작업을 자동 재시작하지 않습니다.
응답 유실로 ERROR/INTERRUPTED가 된 작업은 상태 확인 없이 다시 운전하지 마세요.
로컬 정지는 Pi·USB·UNO가 동작할 때 보내는 소프트웨어 정지이며,
실물 비상정지 회로의 대체 기능은 아닙니다.

상태 보고: POST /api/devices/uno-pi/poll
영상 업로드: POST /api/devices/uno-pi/frame (image/jpeg)
인증: Authorization: Bearer 장비 전용 토큰
ngrok 경고 페이지 우회를 위한 ngrok-skip-browser-warning 헤더는 코드에 포함됨.
Pi의 runtime/에는 로컬 명령 기록과 장비 회차 로그가 저장됩니다.
중앙의 REMOTE_COMMANDS, REMOTE_DEVICES, REMOTE_RUN_CONTROL,
EQUIPMENT_RUNS 및 기존 주문·매핑 테이블로 명령과 결과를 추적합니다.

7. 선택 사항: 부팅 시 자동 시작
-----------------------------
raspi_agent/mobot-agent.service.example의 REPLACE_WITH_PI_USER를
실제 Pi 사용자명으로 모두 바꾸고 경로를 확인합니다.

  sudo cp raspi_agent/mobot-agent.service.example /etc/systemd/system/mobot-agent.service
  sudo systemctl daemon-reload
  sudo systemctl enable --now mobot-agent
  journalctl -u mobot-agent -f

자동 시작은 장비 연결만 준비합니다. 실제 운전 시작은 WPF에서 요청해야 합니다.

8. 중앙 PC 설정과 데모로 되돌리기
---------------------------------
중앙 Flask는 instance/remote-equipment.json의 mode=REMOTE를 사용합니다.
ngrok은 중앙 PC의 localhost:8000으로 연결되어 있어야 합니다.
서버는 127.0.0.1로 유지해도 ngrok을 통해 접속 가능합니다.

  .\Start-MOBOT.cmd
  ngrok http 8000 --url=https://YOUR_TUNNEL.ngrok-free.dev

ngrok 도메인 사용 권한과 실행 중인 터널의 전달 대상은 해당 ngrok 계정에서 확인합니다.
데모로 돌아가려면 instance/remote-equipment.json의 mode를 DEMO로 바꾸고
중앙 서버를 재시작합니다. 기존 기록은 삭제하지 않습니다.

토큰 재발급 또는 DEMO 에이전트 시험은 중앙 PC에서 수행합니다.
  .\.venv\Scripts\python.exe manage_devices.py --url https://YOUR_TUNNEL.ngrok-free.dev --hardware-mode DEMO --activate
이 명령은 토큰을 재발급합니다. 새 instance/raspi-config.json을 Pi의
raspi_agent/config.json으로 복사하고 Pi 에이전트와 서버를 재시작합니다.
실물 모드 복귀 시 같은 명령에서 --hardware-mode LIVE를 사용합니다.
실행 중인 회차가 있으면 재등록을 거절합니다.

검증 범위
---------
Windows의 분리된 Flask·에이전트 프로세스 및 WPF를 이용해 HTTP 명령,
OpenCV 데모 QR, 영상, DB 배정·배출 확인을 검증합니다.
실제 Pi OS·실물 USB·모터·카메라·외부 네트워크 운전은 Pi에 설치한 뒤 확인해야 합니다.
