# 미조립·미검사 운송 시험

`Start-MOBOT-Transport-Test.cmd`로 시작합니다. 실행 중인 일반 서버가 있으면 먼저 종료하세요. WPF는 같은 `http://127.0.0.1:8000`에 연결하고 기존 계정으로 로그인합니다. 화면 상단의 **운송 시험 · 조립·YOLO 생략 · 시험 DB**를 확인하세요.

이 모드는 장비 없는 SIMULATION과 다릅니다. LINE·AGV는 실제 `/device/v1` 연결을 사용하며, 카메라 1에서 실제 QR 판독·주문 배정을 마쳐야 벨트가 출발합니다. 카메라 4는 실시간 관제에 사용합니다. 카메라 2·3과 로봇팔 준비는 시작 조건에서 제외합니다. 실물 LINE·AGV 주소, 인증키, UNO 실측 프로필, 카메라 1·4 연결은 여전히 필요합니다.

순서:

1. 시험 웹에서 주문 → WPF 제작 수락
2. 실제 액추에이터 배출 완료 → QR 판독 → DB 배정
3. 실제 IR1 정차 → 위치 보정·로봇팔 조립 생략 → IR2 이동·정차
4. 실제 AGV 인수·암실 도착 → 암실 QR·YOLO 검사 생략
5. 주문 주소의 HUB로 실제 운송·하역 → 2번 정차·지게 85° 복귀 확인

실제 배출·이동·하역의 접수만으로 단계를 넘기지 않습니다. QR 실패·통신 단절·장비 재부팅은 기존과 같이 운전을 보류합니다. 정지·해제는 이 모드에 참여하는 LINE·AGV 두 장비의 완료를 모두 확인합니다.

시험 기록에는 ASSEMBLY_SKIPPED, INSPECTION_SKIPPED, TRANSPORT_TEST_COMPLETED를 남깁니다. 검사 결과·사진·가짜 PASS는 만들지 않습니다. AGV 계약의 inspection_id는 이번 시험에서는 검사 생략 이력의 routing_reference_id와 연결하는 배송 추적 ID이며, 검사 수행 증거가 아닙니다. 운송 종료 상태는 COMPLETED지만 품질 outcome은 OPEN으로 유지하고 WPF는 **시험 운행 완료 · 미조립·미검사**로 표시합니다.

전용 DB는 `instance/transport-test/mobot.sqlite3`입니다. 최초에 운영 DB에서 계정과 팔레트 마스터 상태만 가져오며 주문·세션·생산 이력은 복사하지 않습니다. 재고도 시험 DB의 독립 값입니다. 팔레트가 운영 DB에서 READY가 아니면 시험 DB에서도 사용 불가로 시작합니다. 시험 후 회수·재적재는 현장 확인이 필요하며 팔레트를 자동 READY로 돌리지 않습니다.

재실행할 때 시험 주문·이력·계정 스냅샷을 유지합니다. 초기 계정 복사 이후 운영 계정의 변경 사항이 자동 동기화되지는 않습니다. 장비 주소·키·카메라 설정은 시작 시 운영 `instance/factory-v1.json`에서 전용 설정 파일로 복사합니다. 운영 또는 시험 회차가 진행 중이면 시작 도구가 전환을 거절합니다. 두 DB는 실행 모드를 바꿔 교차 사용하지 못하도록 표식으로 검사합니다.

운영↔시험 모드를 바꿀 때는 모든 장비의 현재 회차가 끝나고 출력이 정지했는지 먼저 확인합니다. 새 DB로 처음 전환할 때 장비 연결 모듈도 정지 상태에서 재시작해 새 boot_id로 연결합니다. 이전 DB의 완료 이벤트를 새 DB의 작업으로 처리하지 않습니다. 미확인 동작이 있다면 먼저 현장 대조해야 하며 장비의 기록 DB를 삭제해서 우회하지 않습니다.

일반 제작 모드로 돌아가려면 시험 서버를 종료하고 `Start-MOBOT.cmd`를 새 창에서 실행합니다. 환경변수를 직접 설정한 PowerShell에서는 MOBOT_V1_MODE와 MOBOT_DB를 제거한 뒤 실행하세요. 일반 모드는 다시 로봇팔·비전 및 네 카메라의 준비를 모두 요구합니다. 이번 시험은 실물 통합 시험을 대체하지 않습니다.
