# UNO 모의 로봇팔 작업 시험판

기존 로봇팔 완료 신호 버전과 Pi 버전을 보존하고 별도 폴더에 만들었습니다.
이 시험판은 UNO가 전체 순서를 실행합니다. 실제 로봇팔 완료 신호 대신 정해진 시간 동안 벨트를 멈춥니다.
웹/Python은 QR 판독·표시·시간 설정 전송·기록·DB를 담당합니다.

## 기본 동작

액추에이터 전진 10초 → 대기 0.5초 → 액추에이터 복귀와 벨트 운전 동시 시작.

1. IR1(D4) 감지 후 벨트를 5.5초 더 구동합니다.
2. 벨트를 정지하고 3초 기다립니다. 이 시간을 로봇팔 작업으로 가정합니다.
3. 벨트를 자동 재구동합니다.
4. IR2(D2) 감지 후 2초 더 구동하고 최종 정지합니다.
5. 액추에이터 복귀와 최종 벨트 정지가 모두 끝나면 회차를 종료합니다.

작업 가정 대기 시간은 벨트 정지 시간입니다. 액추에이터 복귀는 별도 10초 타이머로 완료됩니다.
QR은 PALLET-숫자를 자동 판독하고 벨트를 정지시키지 않습니다. 미인식이면 모터 순서는 마치되 DB/성공 확인을 차단합니다.

## 웹의 세 시간 메뉴

화면 왼쪽 아래 “시간 설정” 탭이 기본으로 열립니다.

| 항목 | 기본값 | 조절 단위 |
|---|---|---|
| IR1 감지 후 벨트 구동 | 5.5초 | 0.5초 / 1초 / 2초 |
| 로봇팔 작업 가정 대기 | 3초 | 0.5초 / 1초 / 2초 |
| IR2 감지 후 벨트 구동 | 2초 | 0.5초 / 1초 / 2초 |

각 줄에서 단위를 선택한 뒤 − 또는 +를 누르면 그만큼 줄이거나 늘립니다.
클릭할 때 전체 세 설정을 UNO로 보내며, UNO의 같은 설정/요청 번호 응답을 받은 뒤 화면 값을 갱신합니다.
“UNO 적용 확인”을 확인한 다음 운전하세요. 응답 대기/실패 상태에서는 새 자동 운전과 수동 이동을 막습니다.
실패 시 “다시 적용”을 누릅니다. 시간 설정 버튼은 모터 시작 명령을 보내지 않습니다.

- 운전·수동 이동·결과 확인 중에는 시간 변경을 막습니다. 회차 시작 시 설정을 복사해 회차 도중 바뀌지 않습니다.
- IR1/IR2 구동 지연 범위는 각각 0~25초, 작업 대기는 0~30초입니다. 기본 최소 단위는 0.5초입니다.
- 0초는 감지 직후 정지 또는 대기 생략을 뜻합니다. 반전 대기 0.5초와 액추에이터 시간은 이 메뉴에서 바꾸지 않습니다.
- 설정은 UNO RAM에만 적용됩니다. 전원 차단/RESET/일반적인 USB 재접속 리셋 후 기본 5.5/3/2초로 돌아옵니다.
- 센서 미감지 보호는 각 벨트 운전 구간 30초입니다. IR 감지가 늦거나 큰 지연을 설정하면 이 보호 제한이 먼저 적용될 수 있습니다.
- 기존 실제 로봇팔 완료 신호 버전의 재배출 3초 제한은 그 폴더에 그대로 있습니다. 이 자동 모의 작업 시험판은 별도 흐름입니다.

## 사용 방법

최초 적용 시 새 firmware/RobotWorkSimulation/RobotWorkSimulation.ino를 UNO에 업로드합니다.
기존 PalletQRIRTest 및 PiIOBridge 펌웨어와 혼용하지 않습니다. 배선은 배선_참고.txt에 있습니다.
모터 전원을 분리한 채 펌웨어·센서·USB 연결부터 확인하고 시리얼 모니터를 닫습니다.

이 PC의 새 폴더에는 .venv를 준비했습니다.

```powershell
cd 'C:\Users\3팀\Desktop\프로젝트\pallet_system_uno_sim'
.\.venv\Scripts\python.exe app.py
```

http://127.0.0.1:8080 접속 → UNO USB 포트 연결 → 세 시간 확인/조절 → 시작 위치 확인 → 자동 운전 시작.
실제 장비 모드이므로 자동 시작 버튼을 누르면 모터가 움직입니다.
DB는 기존 환경 변수를 사용합니다. 기본은 조회 전용이며 자동 주문 배정은 --mapping auto를 지정합니다.
DB 성공은 최종 IR2 정지·장비 종료 후 확인합니다. 첫 번째 벨트 정지나 3초 작업 대기를 최종 성공으로 처리하지 않습니다.
주문 완료·매핑 해제·팔레트 재사용은 기존 운영 절차를 유지합니다.

장비 없는 데모:

```powershell
.\.venv\Scripts\python.exe app.py --demo --port 8082
```

http://127.0.0.1:8082 에서 DEMO 연결 후 메뉴를 조절하고 시작합니다.
전진/복귀만 단축하며 세 시간 설정은 실제 초 단위를 그대로 재현합니다. 데모 기본 한 회차는 약 13초입니다.
데모는 실제 USB·카메라·DB를 열지 않습니다.

다른 PC에서는 먼저 다음을 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 수동 조작과 중단

J/K 1초 수동 복구, 전체 정지, 카메라 자동 재연결, QR/로그 기록을 유지했습니다.
시리얼 모니터 115200 baud/New Line에서 a=자동 시작, s=전체 정지, j/k=1초 전진/후진, q=QR 알림입니다.
모니터와 웹 서버는 같은 포트를 동시에 열지 않습니다. 실제 웹 운전 시 모니터를 닫습니다.
작업 대기 중 전체 정지를 누르면 이후 자동 재구동도 취소합니다. 복구 후 자동 재시작하지 않습니다.
IR2가 시작 시 가려졌거나 작업 대기 종료 시 가려져 있으면 운전을 거부/중단합니다.
타이머만으로 실제 원점이나 배출 위치를 증명하지 않으며 실제 장비 확인이 필요합니다.

## 검증

자동 테스트 64개와 UNO 컴파일 통과. 실제 브라우저에서 세 시간 메뉴·0.5/1/2초 증가·감소·적용 확인을 데모로 시험했습니다.
실제 USB/모터/센서 운전 및 실제 MySQL 연계는 미수행입니다. 상세 검증은 VALIDATION.md를 확인합니다.


## UNO USB 자동 재탐색·재연결

처음에는 웹에서 UNO USB 포트를 선택해 연결합니다. 이후 끊기면 1초 간격으로 같은 보드를 재탐색하고 재연결합니다.
USB 시리얼 번호(및 VID/PID), 시리얼 번호가 없으면 USB 위치(및 VID/PID)를 사용해 COM 번호 변경도 추적합니다.
장치를 구분할 수 없거나 후보가 여러 개면 임의로 고르지 않습니다. 시리얼 번호 없는 보드를 다른 USB 소켓으로 옮긴 경우 포트를 직접 다시 선택해야 할 수 있습니다.
웹 포트 목록도 2초마다 갱신합니다. 재연결된 실제 COM 포트와 “재탐색 중” 상태를 표시합니다.
사용자가 해제/재연결 중지를 누르면 자동 재연결을 취소합니다. 서버 종료 시에도 재탐색을 멈춥니다.

재연결 시 정지 명령을 먼저 보내고 올바른 READY 및 정지 응답·시간 설정을 다시 확인합니다.
운전 중 USB 단절 회차는 오류로 유지합니다. 모터 시작·QR·J/K 명령을 자동 재전송하지 않으며 회차도 자동 재시작하지 않습니다.
USB 단절 순간의 실제 소프트웨어 정지는 보장할 수 없으므로 장비 상태를 직접 확인해야 합니다.
UNO가 리셋되면 시간은 기본 5.5/3/2초로 돌아갈 수 있습니다. 화면의 실제 시간·시작 위치를 확인한 후 새 회차를 시작하세요.
올바른 READY가 없는 포트는 해제 후 다시 시도합니다. 다른 펌웨어 READY가 오면 반복 리셋을 피하기 위해 자동 재연결을 중지하고 오류를 표시합니다.

이번 변경은 Python/웹 코드입니다. 이미 RobotWorkSimulation 펌웨어를 사용하는 경우 서버를 한 번 재시작하면 적용됩니다.
가상 USB 포트/장치를 사용한 재연결 테스트 19개를 추가해 전체 64개 테스트를 통과했습니다. 실제 USB 탈착은 이번 작업에서 수행하지 않았습니다.

현재 펌웨어의 PUSH_MS/RETURN_MS는 각각 10000ms입니다. 중앙 서버 통합 시 Python·데모의 시작 응답을 실제 펌웨어와 같은 `ACTUATOR:PUSH_10000MS`로 수정했습니다. 실제 펌웨어 문자열을 추출하는 회귀 테스트를 포함해 자동 테스트 65개를 통과했습니다. 하드웨어 없는 데모는 전진·복귀 구간을 단축합니다. SQLite·WPF 연결은 상위 폴더의 `UNO_DEMO_INTEGRATION.md`를 참고하세요.
