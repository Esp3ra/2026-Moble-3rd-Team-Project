# 시험판 브리핑

기존 아두이노 로봇팔 완료 신호 버전과 Pi 버전을 보존하고 pallet_system_uno_sim 폴더에 분리했습니다.
새 펌웨어 RobotWorkSimulation이 모터 순서와 세 타이머를 UNO 안에서 실행합니다. 실제 로봇팔이나 완료 신호는 필요하지 않습니다.

기본 흐름:
IR1 감지 → 벨트 5.5초 추가 구동 → 3초 정지(로봇 작업 가정) → 벨트 자동 재구동 → IR2 감지 → 2초 추가 구동 → 최종 정지.
액추에이터 복귀는 별도로 완료되며, 복귀와 최종 벨트 정지가 모두 끝나야 회차 종료입니다.

웹 “시간 설정” 메뉴에 위 세 항목을 별도로 배치했습니다. 각 줄에서 0.5/1/2초 단위를 선택해 −/+를 누릅니다.
UNO에 세 시간을 함께 보내며 요청 번호와 값이 일치하는 응답을 받은 뒤 적용 확인으로 표시합니다.
운전 중 변경을 막고 회차 시작 시 사용 시간을 고정합니다. 설정 오류/응답 미확인 상태에서는 새 운전을 막습니다.
설정은 UNO RAM에만 두며 재부팅하면 기본값 5.5/3/2초로 복원됩니다.

QR 자동 인식, J/K 1초 복구, 벨트 HIGH 방향, 카메라 재연결, 주문/DB 및 기록 기능을 유지했습니다.
DB는 첫 번째 정지 후가 아니라 최종 IR2 정지와 전체 장비 종료 후 처리합니다.
기존 서버를 종료하고 새 펌웨어를 업로드한 다음 이 폴더에서 app.py를 실행해야 합니다.

검증: 자동 테스트 64개, UNO 컴파일, 실제 브라우저 데모 메뉴 조작 통과. 실제 장비 시험은 남아 있습니다.


## UNO USB 자동 재탐색·재연결

처음에는 웹에서 UNO USB 포트를 선택해 연결합니다. 이후 끊기면 1초 간격으로 같은 보드를 재탐색하고 재연결합니다.
USB 시리얼 번호(및 VID/PID), 시리얼 번호가 없으면 USB 위치(및 VID/PID)를 사용해 COM 번호 변경도 추적합니다.
장치를 구분할 수 없거나 후보가 여러 개면 임의로 고르지 않습니다. 시리얼 번호 없는 보드를 다른 USB 소켓으로 옮긴 경우 포트를 직접 다시 선택해야 할 수 있습니다.
웹 포트 목록도 2초마다 갱신합니다. 재연결된 실제 COM 포트와 “재탐색 중” 상태를 표시합니다.
사용자가 해제/재연결 중지를 누르면 자동 재연결을 취소합니다. 서버 종료 시에도 재탐색을 멈춥니다.

재연결 시 정지 명령을 먼저 보내고 올바른 READY 및 정지 응답·시간 설정을 다시 확인합니다.
운전 중 USB 단절 회차는 오류로 유지합니다. 모터 시작·QR·J/K 명령을 자동 재전송하지 않으며 회차도 자동 재시작하지 않습니다.
USB 단절 순간의 실제 소프트웨어 정지는 보장할 수 없으므로 장비 상태를 직접 확인해야 합니다.
UNO가 리셋되면 시간은 기본 5.5/3/2초로 돌아갈 수 있습니다. 화면의 실제 시간·시작 위치를 확인한 후 새 회차를 시작하세요.
올바른 READY가 없는 포트는 해제 후 다시 시도합니다. 다른 펌웨어 READY가 오면 반복 리셋을 피하기 위해 자동 재연결을 중지하고 오류를 표시합니다.

이번 변경은 Python/웹 코드입니다. 이미 RobotWorkSimulation 펌웨어를 사용하는 경우 서버를 한 번 재시작하면 적용됩니다.
가상 USB 포트/장치를 사용한 재연결 테스트 19개를 추가해 전체 64개 테스트를 통과했습니다. 실제 USB 탈착은 이번 작업에서 수행하지 않았습니다.

사용자 수정 보존: 현재 펌웨어의 PUSH_MS/RETURN_MS는 각각 10000ms입니다. 이번 UNO 재연결 작업에서 펌웨어는 수정하지 않았습니다. 기존 프로토콜의 PUSH_11500MS 응답 이름은 남아 있으므로 실제 시간은 펌웨어 상수를 기준으로 확인하세요.
