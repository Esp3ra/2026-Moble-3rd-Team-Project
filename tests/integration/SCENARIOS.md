# 주문부터 AGV 복귀까지의 통합 시험

파트를 연결한 뒤 사용할 시험 목록이다. 합의된 시험 계획은 아래 10종을 각각 3회씩 수행하는 것이다. 결과를 기록할 때 모의·실물 환경, 코드·모델·보정 버전, 회차 ID, 검사 시도별 ID, 관련 명령·이벤트 ID를 함께 남긴다.

| 구분 | 입력 또는 상황 | 확인할 결과 |
|---|---|---|
| 정상 경로 1 | 서울 HUB 권역 주문, 검사 일치 | 3번 하역 |
| 정상 경로 2 | 대전 HUB 권역 주문, 검사 일치 | 4번 하역 |
| 정상 경로 3 | 천안 HUB 권역 주문, 검사 일치 | 5번 하역 |
| 재작업 1 | 필수 부품 누락 후 재작업·재검사 합격 | 같은 팔레트·회차에 최초 결함과 재작업 명령·새 검사 ID를 보존한다. 합격 저장 후에만 IR2로 이송한다. |
| 재작업 2 | 오장착 재작업 뒤 재검사에서도 불합격 | 각 시도의 사유·명령 이력을 보존하고 벨트와 AGV는 대기한다. 판정 불가도 WPF에 사유를 표시한다. 상한·반복 실패의 최종 처리는 미정이다. |
| 예외 1 | IR1 정차 후 CAM1 QR 세 번 판독 실패 | 2초 간격 재판독 후 정차 유지, WPF에서 재시도 |
| 예외 2 | IR1 정차 후 CAM1 QR 성공 뒤 배정 저장 실패 | 배정 저장 성공까지 정차·조립 보류, 저장 재시도 시 추가 배출·중복 배정 없음 |
| 예외 3 | 장비 명령 중 통신 단절 | 재연결 후 상태·이력 대조, 결과 불명 시 현장 확인 |
| 예외 4 | 같은 명령·완료 중복 또는 이전 회차·이전 검사의 완료 지연 | 실물 동작과 후속 명령은 한 번만 발생한다. 오래된 합격으로 재출발하거나 다른 하역 완료로 표시하지 않는다. |
| 예외 5 | 첫 팔레트 복귀 전에 두 번째 주문 수락 | 대기열 유지, 첫 사이클 복귀 완료 후 투입 |

정상 및 재검사 합격 경로는 합격 저장 → IR2 이송·정차 → AGV 인수 → 목적지 하역 → 2번 정차·지게 85° 복귀까지 확인한다. 불합격이 지속되는 시험은 이송 차단과 이력 보존을 확인한다. 각 회차에 예상·실제 결과와 근거 로그를 남긴다.

### 서버·DB·WPF 구현 PR에서 추가할 검증

- 기존 SQLite DB를 마이그레이션해 과거 검사·목적지 이력을 조회한다. 같은 회차에서 최초 검사, 결함, 재작업 명령, 재검사 결과가 각각 남아야 한다. 검사 합격 저장에 실패하면 재출발 명령을 발행하지 않는다.
- WPF를 빌드하고 기존 관리자 로그인·컨베이어 시험 모드·CAM1 QR ROI·시작·정지·정지 해제·QR 재시도와 비활성 사유를 확인한다. 상단은 팔레트 배출 → QR 인식 → 조립/검사 → AGV 인수 → AGV 하역 완료 순서다. 인수는 명령 접수, 하역 완료는 서버가 같은 회차·명령의 완료를 확인한 시점에 표시한다.
- 시험 서버의 IR1 5.80초·IR2 1.75초는 감지 후 추가 이송 시간이다. QR 배정 뒤 3초 대기는 모의 조립이다. 정식 흐름이 조립 완료·대기 자세와 검사 합격 저장을 기다리는지 별도로 확인한다.
- 로봇팔·AGV·YOLO 실물 연동 또는 정식 Pi–UNO v1 검증이 남은 구현 PR은 Draft로 제출한다. PR에는 모의 시험과 실물 결과를 구분해 기록한다.
