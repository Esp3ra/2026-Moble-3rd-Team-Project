# WPF 주문 관제

기준 시안: `docs/02_관제형.html` (2026-11-16 사용자 제공 로컬 참고 자료이며, 이 WPF 소스 배포에는 포함하지 않음).

## 실행

Windows와 .NET 10 SDK에서:

```powershell
dotnet build .\RobotFactory.sln -c Release
dotnet run --project .\RobotFactory.Admin\RobotFactory.Admin.csproj
```

Visual Studio에서는 `RobotFactory.sln`을 열면 됩니다. `RobotFactory.Admin` 프로젝트가 연결되어 있으며, F5로 실행할 수 있습니다.

## 웹 주문 연결

상위 폴더의 주문 서버가 사용하는 SQLite 주문을 기존 `GET /api/orders` API로 조회합니다. 접수 주문 목록은 3초마다 최신 100건으로 갱신됩니다. 주문을 선택하면 회사명, 전화번호, 주소, 모델, 머리·왼팔·오른팔, 목적지, 상태와 접수 시각을 표시합니다. 새 주문이 도착해도 현재 선택한 주문을 유지합니다. 접수 시각은 관리자 PC의 현지 시간으로 표시합니다. 팔레트 현황도 `GET /api/pallets`로 3초마다 조회하며, DB에 등록된 모든 팔레트의 일련번호·상태·순환 횟수·갱신 시각을 표시합니다. 팔레트 수는 응답 건수로 표시하고 목록을 스크롤할 수 있습니다. 갱신 시각은 관리자 PC의 현지 시간이며 마우스를 올리면 날짜와 시각을 확인할 수 있습니다.

실행 전에 **서버 담당자에게 서버 주소와 관리자 계정을 전달받아야 합니다.** WPF 앱을 실행한 뒤 **로그인 화면의 '서버 주소' 칸에 전달받은 주소를 입력**하고 아이디와 비밀번호로 로그인하세요. 주소는 프로토콜과 포트를 포함한 기본 주소로 입력합니다. 예를 들어 같은 PC에서 서버를 실행하면 `http://127.0.0.1:8000`을 사용하고, 다른 PC에서 실행하는 서버는 담당자가 알려준 실제 주소를 사용합니다.

`MOBOT_API_URL` 환경 변수는 로그인 화면에 처음 표시할 주소를 지정하는 선택 사항입니다. 로그인 화면에서 주소를 직접 바꿀 수 있습니다.

서버는 다음 API를 제공해야 합니다.

- `POST /api/auth/login`, `POST /api/auth/logout`
- `GET /api/orders`, `GET /api/pallets`
- `POST /api/orders/{id}/cancel`

이 브랜치의 `examples/mobot-preview/`는 앞서 공유한 웹 주문 서버입니다. 해당 서버에는 이번 WPF가 요구하는 로그인·팔레트 조회·주문 취소 API가 포함되어 있지 않으므로, WPF 연결에는 위 API를 지원하는 서버가 필요합니다.

로그인 화면에서 서버 주소, 아이디, 비밀번호를 입력하고 **로그인**을 누릅니다. 서버는 `ACCOUNTS`의 비밀번호 해시를 검증하고 8시간 유효한 세션을 발급합니다. 앱 상단에 이름·권한·아이디를 표시하며 로그인 후 주문·팔레트를 자동 조회합니다. 로그인하지 않은 상태에서는 관제 화면에 진입할 수 없습니다.

비밀번호와 세션 토큰은 앱의 파일에 저장하지 않습니다. DB에는 비밀번호 해시와 세션 토큰 해시를 저장합니다. **로그아웃**하면 서버 세션을 해제하고 앱의 주문·팔레트 목록을 비웁니다. 세션 만료 또는 서버의 인증 거절 시 로그인 화면으로 돌아갑니다. 서버 연결 오류 시 마지막 수신 목록을 표시하며 재시도합니다.

서버에 등록된 1차 관리자(`OPERATOR`) 또는 최상위 관리자(`ADMIN`) 계정으로 접속합니다. 계정 발급과 권한은 서버 담당자에게 확인하세요.

## 주문 드롭

주문 목록에서 대기 주문을 선택한 뒤 **검사 · 선택 주문** 영역 하단에서 **재검 요청** 옆의 **주문 드롭**을 누릅니다. 회사명과 주문 번호가 표시된 확인 창에서 승인하면 서버가 주문 상태를 `CANCELED`로 저장하고 WPF 목록에서 제외합니다. 주문 기록은 DB에 보관됩니다. 취소된 주문은 관리자 조회 API의 이력에 포함되며 WPF에서는 숨깁니다.

생산 대기(`PENDING`) 상태이며 활성 팔레트 배정이 없는 주문을 처리합니다. 서버가 현재 상태를 트랜잭션 안에서 다시 확인하며, 진행·완료 주문 또는 팔레트 점유 중인 주문은 거절 사유를 표시합니다. 서버 연결 오류와 처리 중에는 버튼이 비활성화됩니다. 동일 주문의 취소 요청을 재전송하면 기존 취소 결과를 반환합니다.

## 화면 구성

- C# WPF 관제 화면과 로그인 화면의 XAML 배치
- 공통 색상·버튼·카드 스타일
- View와 ViewModel 분리, 실제 주문 API 응답 바인딩
- 계정 로그인, 사용자·권한 표시, 로그아웃과 세션 만료 처리
- 설비 상태는 일시정지 왼쪽에 한 줄로 배치
- CAM 01 검사 영역과 CAM 02·03 추가 영상 자리
- 검사 결과 아래 주문/QR 대조, 오른쪽 팔레트 현황
- 1920×1080 기준 최대화 창과 확대된 카메라 영역
- 하단 확인 필요·최근 이벤트는 기존 128 높이이며, 전체 레이아웃을 창에 맞춰 비례 표시해 화면 전체 스크롤 없이 확인

계정 인증과 주문·팔레트 조회, 대기 주문 드롭을 연결했습니다. 생산 승인·처리, QR 판정, 카메라, 로봇팔, 컨베이어, AGV 연결 및 제어는 후속 구현입니다. 해당 버튼은 비활성화되어 있으며, 실물 정지를 보장하지 않습니다. 공정 이벤트·경보 영역은 HTML 시안의 예시입니다. 팔레트 현황은 실제 DB 조회값입니다.

## 구조 및 후속 연결점

- `MainWindow`: 화면 껍데기, 상단 공통 영역
- `Views`: 로그인 및 관제 화면
- `ViewModels`: 화면 탐색, 주문 선택과 자동 갱신
- `Services/OrderApiClient.cs`: 관리자 주문·팔레트 조회와 주문 드롭
- `Services/AuthApiClient.cs`: 계정 로그인·로그아웃 API 및 계정·세션 모델
- `Resources/Theme.xaml`: 공통 스타일

실제 영상은 `DashboardView`의 CAM 자리에서 ImageSource 또는 영상 뷰로 연결합니다. 실제 정지 버튼은 요청/전송/응답/설비 정지를 구분해 구현해야 합니다.

이 폴더는 WPF 관제 화면과 주문 조회 연결을 포함합니다. GitHub Actions의 `WPF skeleton build`는 이 솔루션의 Release 빌드를 검사합니다.
